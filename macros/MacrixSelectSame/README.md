# Select Similar Objects — CorelDRAW VBA Macro

A selection-only tool: pick one object, choose which properties matter, and
it selects every other object on the page/document/layer that matches on
those properties. It never edits fill, outline, size, nodes, or position —
the only thing it changes is which objects are selected.

## Files

The source code is organized into `src` and `forms` directories for easier synchronization with CorelDRAW:

| File                     | Type           | Purpose                                              |
|--------------------------|----------------|-------------------------------------------------------|
| `src/mdlTypes.bas`            | Standard module | `TCriteria` / `TScanOptions` shared record types      |
| `src/clsRefProperties.cls`    | Class module    | Caches every reference-object property once           |
| `src/mdlUnits.bas`            | Standard module | Temporarily normalizes the document to millimeters    |
| `src/mdlCompare.bas`          | Standard module | All `IsSameXxx` comparisons + `IsSimilarObject`       |
| `src/mdlScan.bas`             | Standard module | Page/layer/group traversal + applies final selection  |
| `src/mdlMain.bas`             | Standard module | `SelectSimilarObjects` — the macro entry point         |
| `src/mdlFormBuilder.bas`      | Standard module | Auto-builds the `frmSelectSimilar` UserForm dynamically|
| `forms/frmSelectSimilar.frm`  | UserForm        | (Generated by builder) The dialog UI and logic         |

## Developer Sync Scripts

If you edit the macro inside CorelDRAW, you can sync the changes back to this repository using the provided PowerShell scripts in this folder's `scripts` directory:

- **`Sync-From-GMS.ps1`** — Extracts modules and forms from the running CorelDRAW instance into the `src` and `forms` directories.
- **`Sync-To-GMS.ps1`** — Pushes `.bas`, `.cls`, and `.frm` files from `src` and `forms` into the CorelDRAW VBA project.

## Installation

### The Easy Way (PowerShell)
1. Close CorelDRAW if it's open.
2. Run `.\scripts\Sync-To-GMS.ps1` in PowerShell. This automatically creates the CorelDRAW project and imports all the `.bas` and `.cls` modules.
3. Open CorelDRAW, then press **Alt+F11** to open the Macro Editor.
4. Go to **Tools → References** and check **Microsoft Visual Basic for Applications Extensibility 5.3**.
5. Open the `mdlFormBuilder` module, put your cursor inside `BuildSelectSimilarFormWithCode`, and press **F5**. This will automatically generate the `frmSelectSimilar` UserForm with all UI controls and code perfectly wired up!
6. Click the **Save** (disk) icon in the VBA Editor to save the `.gms` file.

### Manual Import
1. Open CorelDRAW.
2. **Tools → Macros → Visual Basic Editor** (Alt+F11).
3. Ensure **Tools → References → Microsoft Visual Basic for Applications Extensibility 5.3** is checked.
4. Right-click your VBAProject → **Import File...**
5. Import all `.bas` and `.cls` files from the `src/` directory.
6. Open the imported `mdlFormBuilder` module and run `BuildSelectSimilarFormWithCode` (F5) to dynamically construct the UserForm.
7. **Save** the document/GMS (Ctrl+S in the VBA editor).

### Assigning a shortcut key or toolbar button

- **Shortcut key:** Tools → Customization → Commands → find
  `SelectSimilarObjects` under your macro project → assign a shortcut on
  the *Shortcut Keys* tab (e.g. `Ctrl+Alt+S`).
- **Toolbar button:** same Customization dialog, *Commands* tab → drag
  `SelectSimilarObjects` onto any toolbar. Give it an icon/label as you
  like.

### Running it

1. Select one object.
2. Run **Select Similar Objects**.
3. Check the criteria you care about (or click a preset).
4. Click **Find Matches** to see a count.
5. Click **Select Matches** to actually apply the selection.
6. **Close** when done — this also restores your document's original
   measurement unit (the macro temporarily switches it to millimeters
   during the scan so comparisons are unit-independent; see
   `mdlUnits.bas`).

## CorelDRAW version compatibility

This was written against the standard CorelDRAW VBA object model
(`VGCore`) that has been stable from CorelDRAW X7 through the current
2024/2025 releases, using only documented, commonly-available members:
`Shape`, `Fill`, `FountainFill`, `Outline`, `Color`, `Curve`/`Nodes`,
`Page`, `Layer`, `Shapes`, `ShapeRange`, `Bitmap`, `Text`/`Story`.

A few members are known to vary slightly by version or may not be exposed
identically on every install. These are isolated and wrapped in
`On Error Resume Next` so a missing/renamed member fails just that one
criterion instead of crashing the macro:

- **`Fill.Transparency.Amount`** — transparency object model has changed
  across versions; verify the exact path via the Object Browser (**F2** in
  the VBA editor, search "Transparency") for your installed version if the
  Transparency checkbox behaves unexpectedly.
- **`Bitmap.GetResolution` / `Bitmap.SizeWidth` / `Bitmap.SizeHeight` /
  `Bitmap.Mode`** — double-check these against Object Browser too; older
  versions may expose resolution as separate `ResolutionX`/`ResolutionY`
  properties instead of a `GetResolution` method.
- **`Fill.Pattern.Type`** — pattern-fill comparison is intentionally
  shallow (type only); CorelDRAW's 2-color vs. full-color vs. bitmap
  pattern properties differ enough between versions that a byte-for-byte
  comparison isn't attempted.
- **Mesh / Texture / PostScript fills** — not compared beyond fill type
  (documented limitation, spec section 4).

Before relying on this in production, run the test procedure below once
against your actual CorelDRAW version.

## Known, deliberate behaviors (not bugs)

- **Locked objects:** CorelDRAW's selection API cannot add a locked object
  to a selection. If "Include Locked Objects" is checked, matching locked
  shapes are unlocked so they can be selected — there's no way around this
  within the API, and the macro tells you how many objects were affected.
- **"Ignore Rotation" for size:** when checked, size compares the shape's
  own `SizeWidth`/`SizeHeight` (rotation-independent). When unchecked, it
  compares the on-page bounding box, which does change as an object is
  rotated — this matches spec section 7's "Option A vs Option B" choice.
- **"All Layers" scope** scans every layer on the *current page*. If you
  need every layer across every page, combine "All Pages" scope with a
  second pass, or ask to extend `CollectCandidates` — it's a small change
  in `mdlScan.bas`.
- **"Within Current Selection" scope** is meant for when you've
  shift-selected several objects before running the macro: the first/
  active shape is treated as the reference, and candidates are the other
  selected shapes.

## A note on TabIndex

Control `TabIndex` values in the `.frm` are numbered sequentially across
the whole form rather than restarted per-frame. VB6/VBA silently
renumbers these to be contiguous within each container the first time you
open or save the form in the editor — this is cosmetic (Tab-key order
only) and not something to worry about.

## Test procedure

Build a test page with:

1. Two rectangles, same size/fill/outline, one rotated 30°.
2. A third rectangle with a different fill color.
3. An ellipse with the same fill/outline as rectangle #1.
4. A curve with 12 nodes, and a second curve with 8 nodes.
5. Two text objects, one Artistic, one Paragraph, different fonts.
6. A group containing a rectangle identical to #1, nested inside another
   group.
7. One locked object and one hidden object that would otherwise match.

Suggested checks:

- Select rectangle #1, check **Object Type + Same Size + Full Color +
  Outline Color + Outline Width**, click **Exact Match** preset, **Find
  Matches** → should find rectangle #2 (rotation doesn't affect
  `SizeWidth`/`SizeHeight`) but not the differently-colored rectangle #3,
  and not the ellipse (different type).
- Uncheck **Object Type**, re-run → the ellipse should now also match
  (same fill/outline/size, different type ignored).
- Select a curve, check **Node Count** only → only the curve with the same
  node count should match.
- Enable **Search Inside Groups**, re-run a size/fill match against
  rectangle #1 → the nested rectangle inside the double group should be
  found.
- Disable **Search Inside Groups** → the group itself becomes a single
  candidate; it won't match a Rectangle-type search.
- Leave **Include Locked Objects** / **Include Hidden Objects** unchecked →
  the locked/hidden test objects should be excluded even if their
  properties match; check them → they should now appear, with a message
  confirming the locked one was unlocked.
- Uncheck every criterion and click **Find Matches** → you should see
  "Please select at least one comparison criterion."
